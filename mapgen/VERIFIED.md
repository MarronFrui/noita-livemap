## 2. RNG machinery

- **Core (Lehmer/Schrage, minstd):** `Next(): v = 16807*(int)Seed − 2147483647*((int)Seed/127773)`; `if (v <= 0) v += 2147483647`; `Seed = v; return Seed / 2147483647`. All integer division is C truncation. `NextU() = Seed * 2⁻³¹ * 2147483645`; `Random(a,b) = a + (int)((b+1−a)*Next())`; `SetRandomFromWorldSeed(s)`: halve if `s ≥ 2147483647`; `NewNollaPrng(x)`: seed = x, one warm-up `Next()` discarded. **Game-verified ✅: 100.00% match on 2,113,568 draws across 4 seeds** (probe mod `mods/noita-livemap-rng-probe/`, after the signed-i32 `>>> 0` fix) — ABOUT_MATH §2, §7.1.
- **`Next()` returns a double:** asm-verified that poro `Next()` (FUN_010098c0) advances the state AND returns `state × 4.656612875e-10` in XMM0; every consumer multiplies by 2147483645 (constant @0x11e0210) and trunc-converts to u64 (FUN_01033781 = `__dtoui64`). So `nextU() = trunc(state × 4.656612875e-10 × 2147483645)` — the JS port is exact. 🔬 ABOUT_MATH §7.8.
- **`SetRandomSeed` mixer** (diddle table backward-index, `&3` warm-up loop, Schrage core) = FUN_0048fd30, calibrated step-for-step against our JS; assert leaks `poro/source/utils/random/random.cpp`. **Does NOT drive the wang fill** (proven by lab + 644M sweep). 🔬 ledger "Verified anchors".
- **The fill's RNG** = poro Random on a **thread-local state** (TLS+0x14, lazily allocated by FUN_008ebf00, whose unconditional tail `Next()` is absorbed by the seed convention). 🔬 ABOUT_MATH §7.7, §7.9.
- **All fill draws are `nextU() % m`:** vertex coloring (0x8eca9e), rep-reduce reroll (0x8ec950, `(p+1+rand%(cc−1))%cc` or weighted), choose-tile (0x8ec855, 2-pass count-then-pick, one draw per placement). 🔬 ABOUT_MATH §7.8.
- 16807 is a **primitive root** mod 2³¹−1 (order 2147483646) → orbit distances are well-defined; every nonzero state is reachable. ✅ (computed) ABOUT_MATH §7.9.
- Ruled out as fill sources: the global poro stream (order-independence), the global LCG ×214013+2531011 (all consumers are gameplay), mt19937 / 64-bit LCGs (0 fingerprint hits). See §8.

## 3. Wang atlas format

- **Header** = last 9 RGB bytes of the image's FIRST row, decoded as `header[i] = byte[w*3−1−i] ^ (i*55)`, truncated to uint8 (`& 0xFF` on encode AND decode). `header[7] == 0xC0` → corner-type (`num_color[0..3]`, `vary_x = h[4]`, `vary_y = h[5]`, `short_side_len = h[6]`); else edge-type (`num_color[0..5]`, `vary = h[6]/h[7]`, `short = h[8]`). ✅ ABOUT_MATH §3.1.
- **Packing** (stbhw `__process_template`): 3 px separators, +1 px content offset; h-tile = `2s×s` px, v-tile = `s×2s`; each tile carries 6 corner constraints (a,b,c top/left; d,e,f bottom/right). The **variants loop** (`vary_x`/`vary_y`: every constraint combo appears ×N with distinct pixel art) is part of the walk — found & fixed missing from our port via the `wang_gen.exe` diff. ✅ ABOUT_MATH §3.1, §6.
- **All 31 game atlases are corner-type except winter_caves (edge-type)**; dims recompute exactly from the template formula; sparse per-vertex-class color counts (coalmine `(1,2,1,2)` s=13 → 72h+72v; excavationsite `(1,2,1,2)` s=20 → 32h+32v; liquidcave/snowcave `(1,2,1,2)` s=20/26; crypt `(2,1,3,1)` s=22; fungicave `(3,1,3,1)` s=13 …). ✅ ABOUT_MATH §3.1.
- **Key consequence:** with these sparse sets every 6-corner constraint combo has exactly ONE tile → tile choice is uniquely determined by the vertex color grid; the only randomness is the vertex coloring itself. ✅ ABOUT_MATH §3.1.
- `tools_modding/wang_gen.exe` is template-side only (artist canvas; no seed, no fill); our template walk reproduces it byte-identically (coalmine + winter_caves params). ✅ ABOUT_MATH §6 (2026-09-03).

## 4. The fill — walk mechanics (measured-correct)

The accepted fill attempt is fully determined by ONE number: the sub-RNG state
**S** that `CreateHerringboneWang_Threaded` seeds the TLS Random with. Given
the correct S, the following mechanics reproduce the game exactly:

- **Vertex grid:** `xmax = w/s+6`, `ymax = h/s+6` (binary row stride 0x6a = 106); for the lab rect the key grid is `(H+4)/4+6` = 70×32. 🔬 ABOUT_MATH §7.7, §7.9.
- **Class formula: `p = (i − j + 1) & 3` in generation space** (row counter starts at 1 and DECREMENTS — asm 0x8eca4b `MOV EBX,1` … 0x8ecacd `DEC EBX`). In key space (after the 1-vertex-row discard from the +4-row discard) this equals the lab's empirical `(I−J)&3`; binary classes at `(I−J)&3 ∈ {0,2}`, classes {1,3} are single-color 0 — a built-in skeleton (~half the vertices are seed-independent). 🔬 + ✅ ABOUT_MATH §3.2, §7.8, §7.6.
- **Vertex coloring:** one `nextU()` per vertex, row-major scan: `c_color[j][i] = nextU() % cc[p]`. **Measured ✅:** with the correct S, 1206/1218 informative vertices exact across three independent seeds (498/500, 325/327, 395/403 post-reduce; chance ≈ 2⁻¹⁰⁰⁰). ABOUT_MATH §7.9.
- **Repetition-reduction pass** (default ON, gated cc>1): re-colors vertices where the 3×2 neighborhood matches fully; flips ~11% of informative vertices (calibrated 8.8–12.9%). ✅+🔬 ABOUT_MATH §3.2, §7.9.
- **Herringbone scan:** `ypos = −s`, `j = −1`, `phase = j&3`, column start `i = phase ? phase−4 : 0`, step 4; h-tiles consume vertices `[j+2..j+3][i+2..i+4]`, v-tiles `[j+2..j+4][i+5..i+6]`. The game's 464-placement log aligns **464/464** to the simulated scan at `log = sim + (3,−1)` in cell coords. (Tile-ID choices differ 30/464 only because our port reads a different constant vertex offset than the game — port convention, not model; the lab tileset is fully forced so picks are unambiguous given the vertices.) ✅ ABOUT_MATH §7.9.
- **Output mapping:** output px (0,0) ↔ vertex (2,2); vertex (I,J) ↔ output px `((I−2)·s, (J−2)·s)`; 1 atlas px = 10 world px (scale still 🔗). ABOUT_MATH §3.2.
- **+4-row discard:** the buffer is `(h+4)` rows; the copy loop starts at j=−4 → the top 4 cell-rows are discarded. ✅ in-binary. ABOUT_MATH §3, §7.7.
- **Order-independence:** 100% identical placements across camera paths → the fill uses a LOCAL state, never the global poro stream. ✅ ABOUT_MATH §7.6.

## 5. Pipeline structure

- **Area** = bounding box of one connected component of a biome color on the biome map; dims via `GetWidthFromPix`. ✅ ABOUT_MATH §3.
- **Once per area**, cached by (width, height, seed) across chunks (FUN_0090c1f0). 🔬 ABOUT_MATH §7.7.
- **Area driver** FUN_00904c20 (procedural_terrain.cpp): reads the area object (`this`), computes GetRNG, runs **≤100 attempts**; per attempt `state = Schrage(state)`, `param_9 = (double)state × 4.656612875e-10 × 2147483645`, `CreateHerringboneWang_Threaded(...)`; `hasPath` = FUN_00901780 (JPS) → accept or retry; coalmine/excavationsite string checks → FUN_00901580. 🔬 ABOUT_MATH §7.9.
- **GetRNG (asm-exact):** `d = (double)(int32)C + diddle[C>>31]` (diddle = {0.0, 2³²} @0x11e0ba0 — unsigned promotion); `if (d >= 2147483647.0) d *= 0.5`; ONE warm-up `Next()` on the driver-local Random; `skip = (width % 11)(signed trunc) + ((u32)C % 12)` (width = `[area+0x34]` clamped [1,1024]); advance `skip` inline Schrage. 🔬 ABOUT_MATH §7.9.
- **Dispatch:** the fill runs as an **Init-time thread-pool std::function task** capturing the 0x154-byte area object (ctor FUN_00904b10; `[area+0x4c]` = ctor arg = `WORLDSEED::GetSeed() + DAT_01328010`, written once during the Init walk). Chunk generation at runtime is lazy/streaming. 🔬 ABOUT_MATH §7.8, §7.9.
- **RUNTIME CONFIRMATION (Cheat Engine, 2026-09-08, seed 78633191):** `[area+0x4c]` = raw ws (`EAX = 0x04AFD8E7`, multiple areas, hook at 0x904d3b); the Threaded-layer cache pair (DAT_013276c8/d0) reads `(last param_9, diddled ws = 78633191.0)`; the last fill's accepted state = **ws × 16807^115** — inside the chain's ≤ ~122 (115 = 1 warm-up + skip 14 + A+1 = 100 → w ≡ 3 mod 11, e.g. w = 256 = the Mines width, accepted on attempt A = 99). **The asm-exact chain from worldseed to the fill's sub-seed is confirmed for regular (Init-filled) areas.** ✅
- ⚠️ **THE OPEN LINK:** the driver's input is runtime-confirmed (**C' = raw worldseed**, Cheat Engine hook at 0x904d3b, seed 78633191, 2026-09-08 — `EAX = 0x04AFD8E7` after `MOV EAX,[ESI+4C]`, multiple areas) — but C = ws is **excluded by measurement** as the source of the lab sub-seed (§8 rows 11–12). So the divergence is downstream of the driver's input: between the driver's chain and/or the sub-seed actually passed to `CreateHerringboneWang_Threaded` (FUN_008eda10) — see §9.

- **Reference-frame statement (2026-09-19):** the absolute references are
  THIS file and the probed reference seeds 78633191/92/93 (captures, CE
  anchors, entity dumps, spawn equations). **Coalmine is a stage-6

  (see ABOUT_MATH 2026-09-19 (9)).

- **Constant-offset principle:** a constant offset is only valid if the drift it corrects is zero or sawtooth-shaped; any linear (multiplier) component makes a constant wrong far from where it was measured. (ABOUT_MATH §4.)
- **Paint-immune judging:** spawn equations (each seeded spawn = an exact wang-cell color fact from entity dumps) are the primary judge; geometry-vs-capture metrics are confounded by non-wang layers and density. (ABOUT_MATH §7.3/§7.5, mapcap/README ladder.)
- **Order-independence is a hard constraint:** any fill model must be a local, per-attempt state — the global poro stream is out. (ABOUT_MATH §7.6.)
- **The lab is the instant bench:** the 548/362/451-vertex answer keys (seeds 91/92/93, `out/oracle/lab-vertex-grids.json`) verify any new hypothesis in minutes; a correct model scores ~100%, partial-walk scores are noise. (ABOUT_MATH §7.6, §7.9.)
